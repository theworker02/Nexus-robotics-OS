# Nexus Robotics OS 4.2 Validation

This report is a release-candidate template until the commands below are executed in the target CI and release environments. `NOT RUN` is intentional evidence status, not a pass.

| Area | Command/evidence | Result |
| --- | --- | --- |
| Rust tests | `cargo test --workspace` | NOT RUN |
| Formatting | `cargo fmt --check` | NOT RUN |
| Clippy | `cargo clippy --workspace --all-targets --all-features` | NOT RUN |
| Rust docs | `cargo doc --workspace --no-deps` | NOT RUN |
| CLI simulation | `cargo run -p nexus-cli -- sim scenario warehouse-fetch --no-ai` | NOT RUN |
| Compatibility smoke | `cargo run -p nexus-cli -- compatibility inspect nori-a3` | NOT RUN |
| Website build | `npm ci && npm run build` in `website/` | NOT RUN |
| Website lint | `npm run lint` in `website/` | NOT RUN |
| Docker simulator | `docker compose -f compose.dev.yml run --rm nexus-simulator` | NOT RUN |
| Physical robot | Hardware-specific evidence | NOT RUN |
| HIL | Hardware-specific evidence | NOT RUN |

For external-system blockers and promotion criteria, see [4.2 external validation](4.2-external-validation.md).

For each executed gate, add commit, version, environment, scenario/seed, robot profile, and artifact references. Do not promote a result above the evidence actually produced.
