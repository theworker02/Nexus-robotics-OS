# Nexus Robotics OS 4.2.0 Release Candidate

## Highlights

Nexus 4.2.0-rc.2 consolidates the adaptive robotics runtime, reliable skills, configurable intelligence documentation, simulation, Proving Ground evidence, connected-system foundations, and Rust developer tooling into a release-readiness candidate.

## Why this release matters

This phase improves product truth and contributor experience without claiming that unvalidated hardware, transports, providers, or integrations are complete.

## Adaptive intelligence

Nexus Brain and hardware-aware profiles remain capability-based recommendations. Hardware probing, remote execution, encrypted synchronization, and physical autonomy remain dependent on implementation and validation evidence.

## Skills and safety

Skills remain contract-driven and pass through deterministic capability, permission, limit, resource, watchdog, and Safety Governor checks. Models do not receive raw actuator authority.

## Model Fabric and Connected Intelligence

Model and MCP surfaces are documented as configurable integration boundaries. Provider, remote transport, live MCP, and external-device availability must be verified in the target environment.

## Simulation and integrations

NXR reference robots, VirtualBus, deterministic scenarios, Nori community compatibility, ROS 2 mapping, LeRobot bridge foundations, and Proving Ground reports remain the primary software-verifiable paths.

## Developer experience

The release candidate aligns workspace metadata, public policies, compatibility language, funding, citation, roadmap, website identity, and release documentation around Nexus Robotics OS 4.2.

## Breaking changes

The workspace version moves to `4.2.0-rc.2`. Consumers should not treat this prerelease as stable and should review compatibility and validation status before connecting hardware.

## Upgrade guide

1. Pin the release-candidate version or commit.
2. Run `cargo test --workspace`.
3. Run the documented CLI simulator and compatibility smoke paths.
4. Review `COMPATIBILITY.md`, `SECURITY.md`, `PRIVACY.md`, and the applicable Proving Ground report.

## Known limitations

HIL, physical-robot, vendor-verified, universal-compatibility, live ROS graph, remote model, persistent-memory, and production-autonomy claims are not implied without their corresponding evidence. Unavailable checks must remain `NOT RUN`.

## Validation

The RC validation report is generated separately and must list actual commands, environment, commit, seed, profile, result, and unrun checks. See `docs/releases/4.2-validation.md` when generated.

## Downloads

Release artifacts are not claimed until the RC packaging and release workflow produces and checksums them.
