# Nexus Robotics OS v4.2.0-rc.2 — Complete Public Release Candidate

**Version:** `4.2.0-rc.2`  
**Channel:** Preview  
**Release status:** Release candidate; not stable  
**License:** Apache-2.0

## Summary

Nexus Robotics OS 4.2.0-rc.2 packages the complete post-rc.1 state. It includes the polished developer README, registry-safe crate identities, corrected CI package references, a scheduled crates.io publisher, and the official `nexus-robotics-os` facade crate.

This release remains evidence-first. It does not claim universal robot compatibility, unrestricted model control, vendor certification, HIL validation, live ROS 2 transport, external provider access, or physical-robot validation without corresponding external evidence.

## Highlights

- Workspace and internal package requirements synchronized at `4.2.0-rc.2`.
- Official facade package: [`nexus-robotics-os`](https://crates.io/crates/nexus-robotics-os).
- Registry-safe package identities for previously occupied names, including `nexus-core-1`, `nexus-protocol-1`, `nexus-gateway-1`, `nexus-sdk-1`, `nexus-cli-1`, and `nexusd-1`.
- README expanded with official brand visuals, Mermaid architecture diagrams, detailed setup, simulator, CLI, Docker, testing, package, safety, and integration guidance.
- CI updated to use the renamed CLI package IDs while preserving the `nexus` and `nexusd` binary names.
- Manual and scheduled crates.io publication workflow with version detection, dependency ordering, cooldowns, and immutable-version skips.
- Existing deterministic runtime, capability model, Nexus Brain, VirtualBus, Proving Ground, ROS 2 mapper, LeRobot bridge, and Nori compatibility surfaces retained from rc.1.

## Official facade package

Add the official package to an application with:

```toml
[dependencies]
nexus-robotics-os = "4.2.0-rc.2"
```

The facade re-exports the focused contracts as `nexus_robotics_os::core` and `nexus_robotics_os::runtime`. Applications and adapter authors may continue to depend directly on the focused crates when they need narrower dependency boundaries.

## Validation status

The local software and virtual-hardware paths remain the primary evidence. The following still require external evidence and are not promoted by this release:

- HIL validation
- Live ROS 2 graph transport through the Rust runtime boundary
- External model providers
- Live MCP, BLE, Wi-Fi, MQTT, or device transports
- Vendor verification
- Production autonomy
- Physical robot validation

See [4.2 validation](4.2-validation.md) and [external validation plan](4.2-external-validation.md).

## Upgrade guidance

1. Treat `4.2.0-rc.2` as a preview release.
2. Run `cargo test --workspace` and the documented simulator/compatibility commands.
3. Review `SECURITY.md`, `PRIVACY.md`, `COMPATIBILITY.md`, and the applicable Proving Ground report.
4. Do not connect physical hardware without adapter review, configured limits, emergency-stop procedure, and appropriate validation.
