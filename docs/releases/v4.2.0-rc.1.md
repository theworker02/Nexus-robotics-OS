# Nexus Robotics OS v4.2 — Public Release Candidate

**Version:** `4.2.0-rc.1`  
**Channel:** Preview  
**Release status:** Release candidate; not stable  
**License:** Apache-2.0

## Summary

Nexus Robotics OS 4.2.0-rc.1 is the project’s public release-readiness candidate. It consolidates the Rust-first adaptive runtime, capability-driven skills, Nexus Brain profiling, deterministic Safety Governor boundary, simulation and Proving Ground evidence, integration contracts, release documentation, and contributor-facing tooling into a coherent public distribution.

This release is deliberately evidence-first. It does not claim universal robot compatibility, unrestricted model control, vendor certification, HIL validation, or physical-robot validation without the corresponding external evidence.

## Highlights

- Canonical **Nexus Robotics OS** identity and “Make simple robots capable. Make capable robots yours.” positioning.
- Workspace version `4.2.0-rc.1` with synchronized lockfile and citation metadata.
- Capability-driven NCM contracts and deterministic skill execution.
- Nexus Brain hardware-profile and intelligence-placement guidance.
- SenseHopping, StructureScan, Active Learning, VirtualBus, and Proving Ground foundations.
- Nori community compatibility, ROS 2 capability mapping, and LeRobot bridge surfaces.
- Explicit L0–L5 validation terminology with unearned evidence reported as `NOT RUN`.
- Security, privacy, compatibility, funding, governance, release, and glossary documentation.
- GitHub Pages metadata and release workflow foundations.
- Crates.io-oriented package metadata and versioned internal dependency requirements.

## Safety and authority

Models, external tools, and integrations are advisory or contract-bound. The physical boundary remains:

```text
Goal → Plan → Validation → Safety Governor → Skill → Adapter → Robot
```

No language model or external provider receives raw actuator authority. Emergency stop, vendor limits, capability checks, permissions, resource locks, watchdogs, and no-auto-resume behavior remain deterministic requirements.

## Validation status

The local software and virtual-hardware paths are the primary release evidence. The release report records exact commands and results. The following remain explicitly unvalidated unless external evidence is attached:

- HIL validation
- Live ROS 2 graph transport through the Rust runtime boundary
- External model providers
- Live MCP, BLE, Wi-Fi, MQTT, or device transports
- Vendor verification
- Production autonomy
- Physical robot validation

See [4.2 validation](4.2-validation.md) and [external validation plan](4.2-external-validation.md).

## Compatibility

- NXR-1/NXR-2: deterministic local profiles and simulation paths.
- Nori: community compatibility target with simulated/public profile; no vendor endorsement implied.
- ROS 2: capability mapper and adapter contract; live graph transport remains unvalidated.
- LeRobot: loss-aware episode/data bridge foundation.
- Custom hardware: requires an adapter, configured limits, and hardware-specific evidence.

See the [compatibility matrix](../../COMPATIBILITY.md).

## Upgrade guidance

1. Treat `4.2.0-rc.1` as a preview release.
2. Run `cargo test --workspace` and the documented simulator/compatibility commands.
3. Review `SECURITY.md`, `PRIVACY.md`, `COMPATIBILITY.md`, and the applicable Proving Ground report.
4. Do not connect physical hardware without an adapter review, configured limits, emergency-stop procedure, and appropriate validation.

## Packaging

The workspace is prepared for crates.io metadata and internal dependency version requirements. Publication is dependency-ordered and requires a clean committed tree, package ownership on crates.io, and authenticated registry access. No crate is described as published until the registry confirms it.

## Known limitations

This is not a stable release. Hardware probing, persistent memory, remote execution, live ROS 2 transport, live MCP/device transports, external model providers, package signing, HIL, physical validation, vendor verification, and production autonomy remain implementation- or evidence-dependent.
